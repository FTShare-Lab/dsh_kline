# 多图与绘图交互本地验收（2026-11-18）

状态：本地候选版本，等待人工验收；未推送、未发布 Release、未上传 npm。代码位于 `codex/drawing-interaction-vnext`，基于 `463173c`。

## 范围

- 同一当前图一次请求 1–8 种自动绘图，沿用各自识别规则；合格结果原子应用，无候选单独报告。
- 点击选中绘图，拖动锚点或通过「修改」输入价格；按原 ID 更新、删除。
- 绘图撤销／重做；整组绘图作为一步历史操作，保留当前行情、指标和视口。
- DSH 与 Codex 共用请求定义、识别映射及绘图恢复校验，分别接入宿主应用回执。

## DSH 实测

环境：DSH Web `0.2.1-rc.5`，独立测试 profile，端口 `61071`。使用真实 QQQ 日线行情，222 根，2025-12-31 至 2026-11-17；本轮观察到的数据来源为 `tencent_free`。通过 DSH 原生插件视图实际点击、拖动、键盘输入，并核对本机应用回执与前后对象。

| 案例 | 结果 |
| --- | --- |
| 多选斐波那契与下降通道，一次绘制 | 两个独立对象，一份 `applied` 回执；自动调整视野显示锚点区间 |
| 整组撤销、重做 | 对象数 2 → 0 → 2，恢复原 ID；K 线没有变化 |
| 点击通道选中 | 显示起点、终点、平行点三个手柄；手柄与画布顶点一致 |
| 拖动平行点 | 647.05 → 658.0115155495585；日期、原 ID、其余两个锚点、斐波那契和行情均未变化 |
| 撤销、重做拖动 | 平行点恢复 647.05、再次恢复 658.0115155495585；回执均确认 |
| 输入平行点价格 | 修改为 651，按原 ID 更新；撤销恢复 647.05 |
| 删除选中的通道、撤销删除 | 仅删除通道，斐波那契保留；撤销恢复原通道，不自动恢复选择状态 |
| 缩放、平移 | 对象和锚点保持；操作不作为绘图历史条目 |
| 搜索切换 AAPL，再搜索返回 QQQ | AAPL 没有 QQQ 对象或历史；QQQ 原两个对象恢复，仍可撤销、重做整组绘图 |
| 清除全部绘图 | 两对象清零，成功回执与成功文案一致 |
| 无候选 | AAPL 的 ABC／下降通道不强行生成；QQQ 的严格 ABC 也未强行生成 |

实测过程中修复：价格轴宽度造成手柄横向偏移；清除回执刷新面板后误报状态变化；搜索返回已打开标的时重新抓行情覆盖绘图；选中修改跳到旧工具面板。数值编辑改用紧凑的统一锚点输入行，观察上报不会打断正在输入的数值。

## DSH 自然语言补测

在独立测试会话中实际发送自然语言，由真实 DeepSeek 模型自行选择插件工具；没有将预写工具调用冒充模型执行。模型使用 DeepSeek-V4.1-Flash（High）。每轮同时核对画布、当前观察、正式对象 ID、行情以及已确认应用回执。

| 自然语言请求 | 已核对结果 |
| --- | --- |
| 当前 QQQ 日线，一次画 ABC 和下降通道 | 一次 `draw_chart` 请求包含两种工具；下降通道应用成功；ABC 无合格候选，不伪造几何点位 |
| 修改选中的线：平行点改为 650，其余锚点、日期、样式不变 | 原通道 ID 保持；只有平行点价格 647.05 → 650；行情和其他字段保持 |
| 撤销刚才的修改 | 真正的 `drawing_history/update`，引用原修改操作；平行点恢复 647.05，无新建、删除或普通坐标反向修改 |
| 重做刚才撤销的修改 | 同一原修改引用、方向 `redo`；同一对象平行点恢复 650 |
| 再一次画斐波那契和下降通道，作为一次多图操作 | 一个原子绘图批次新增两个对象；对象总数 1 → 3；先前通道保留 |
| 撤销刚才那一组绘图，保留之前的通道 | 对象数 3 → 1；只移除该批次两个对象，旧通道的 650 平行点与原 ID 保持 |
| 重做刚才那一组绘图 | 对象数 1 → 3；原两对象 ID 一起恢复，引用同一个原绘图批次，不创建副本 |
| 删除当前选中的旧通道，保留新斐波那契和下降通道 | 对象数 3 → 2；只删除所选旧 ID，并清空选择，新批次两个 ID 和行情保持 |

首轮实测发现历史接口只接受 `action=create`，而模型按历史更新语义传入 `update`，随后退回普通价格修改。该轮不计撤销通过。已统一 DSH／Codex 参数约定、保留旧调用兼容、补充回归与工具说明；重新开启独立对话后，上表撤销／重做均经过真实历史恢复接口确认。

QQQ 当期严格 ABC 没有候选，该负向结果保留。两种合格自动工具同时落图的路径已用斐波那契＋下降通道补测；ABC 的真实行情正向流程随后用 SLV 补测，详见下节。

最终核对：全部补测回执均为 `applied`；修改前后和撤销／重做的行情序列逐项一致。自动化回归为 418 项前端／Node、669 项 Python 通过，另有 1 项 Python 跳过、361 个子测试通过。没有推送、发布或上传 npm。

## ABC 真实行情正向补测：SLV

标的：iShares Silver Trust（SLV.US），日线、不复权，已加载 222 根，截止纽约交易日 2026-11-17。来源为 `tencent_free`。先用现有识别器在真实行情中查找合格样本，再在独立 DSH 对话中发送自动绘图请求；没有提供坐标或放宽规则。模型仍为 DeepSeek-V4.1-Flash（High）。

| 锚点 | 纽约交易日 | 原始价格 |
| --- | --- | --- |
| 0（起点） | 2026-10-09 | 55.25 |
| A | 2026-10-14 | 50.01 |
| B | 2026-10-20 | 52.89 |
| C | 2026-10-26 | 47.86 |

- 首轮发现映射遗漏起点：识别器有完整起点＋A/B/C，但自动结果只落 A/B/C，模型再执行一次普通修改补起点。该轮不计“一次自动绘图通过”。
- 修复 DSH／Codex 共用候选映射，缺少起点的 ABC 结果拒绝落图；工具名称移除“三点”限定，四点 ABC 可从已绘对象列表进入统一锚点编辑。识别条件保持原样。
- 重新开启独立对话，自动绘图一次生成四个标签 0/A/B/C 和三段连线。该视图当时只有一份 `applied` 应用记录，类型为原子 `drawing_batch`；没有第二次补画。
- 从已绘对象列表选中后，看到四个锚点手柄及四个价格字段。自然语言指定“只把 C 点改成 48.00，日期及其余锚点和样式不变”，同一 ID 的 C 价变为 48.00。
- 自然语言“撤销刚才对 C 点的修改”使用 `drawing_history/update`，引用该次 C 点修改的确认记录，恢复 47.86。逐项比较：整个对象恢复到最初自动绘制状态；0/A/B、日期、名称、颜色、行情和对象数量均未变化。
- 截图人工核对四个锚点与对应 K 线极值、三段连线、选中手柄及撤销后的 C 点。模型回复的日期也按纽约交易日核对，不采用北京时间的次日日期。
- 新增来自本次真实行情的冻结 60 根日线样本 `tests/fixtures/slv_2026_11_17_abc.json`，回归校验合格候选到四点绘图的投影、极值与交易日期。

这些是当前规则下的一个真实正向样本；不代表其他标的、区间的所有 ABC 候选均已通过人工复核。

## 日期与画布几何反馈补测

- 接口直接返回交易所本地日期，日期输入也用同一时区解析；真实 SLV 四锚点分别返回 10-09、10-14、10-20、10-26，ISO 为纽约收盘时间及 `-04:00`；11-17 行情返回 `-05:00`。DSH 实际模型直接读取这些日期，没有手动减一天。
- ABC 全部显示时，当前反馈为 `inside_plot`；向左平移后为 `partially_clipped`；再次平移，四点均在可视时间范围以前，反馈为 `outside_plot` 且 `time_range_overlap=false`。全程对象 ID、四锚点和已加载行情保持一致。
- 实测发现 SDK 的 `from/to` 在右侧留白时仍含屏幕外缓存数据；改用其 `realFrom/realTo`，并保留旧 SDK 无该字段时的兼容。修复后实际模型重新读当前观察，正确说明 ABC 已不在画布内，未重画或移动对象。
- 在当前视口新增价格 100 的水平线：`time_range_overlap=true`，但 `canvas_visibility=outside_plot`，证明时间覆盖不代表价格在画布内。DSH 模型能正确区分；再用自然语言撤销测试线，对象数 2 → 1，原 ABC、视口和行情保持。最后通过「修改」重新定位 ABC，恢复 `inside_plot`。
- 自动化另覆盖上下裁剪、两端都在画布外但线段穿过绘图区、通道独立边界、矩形填充、无投影 API、旧客户端缺少字段及不能升级成像素验证。

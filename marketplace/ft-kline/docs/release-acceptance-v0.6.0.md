# v0.6.0 私有灰度验收说明

状态：GitHub v0.6.0 发布检查与后续桌面灰度记录。GitHub Release 不等于公共插件目录上架。

## 自动化门槛

- DSH 的完整 Node/Python 回归、首次启动、独立 DSH profile 烟测和原有包清单均通过。
- Codex 测试覆盖：不导入 DSH 图表服务、不读取 DSH 凭据文件、30 分钟会话清理、版本冲突、候选显式确认、同 request ID 重放冲突、UI 渲染失败/回执与像素验证分离。
- Codex MCP 集成覆盖 `ui://ft-kline/chart-v3`、App-only `ft_kline_app_action` 可见性与输出 schema、完整受控绘图链、CLI 降级、无 Key 和 Key 不回显。
- DSH 与 Codex 包都需在全新目录、中文及空格路径、无缓存凭据环境下解压验证；两个清单、版本、资源 URI 和 `${PLUGIN_ROOT}` 启动路径由包检查验证。

## 绘图验收口径

Codex 桌面图表的手动工作台提供 **9 个入口**：水平线、趋势线、平行通道、平台框、斐波那契、ABC 手动选点，以及 SMA、EMA、BOLL 指标落图。SMA 与 EMA 共用 `series_line` 命令类型；这 9 个入口不能写成“十类图形均可手动创建”。

受控编辑协议覆盖 **10 类图表命令**：水平线、趋势线、通道、矩形、斐波那契、标记折线、注释、指标线、价格带、价格柱。注释还细分为文字、数字和图标。未出现在手动工作台中的类别按对话工具链及自动化测试核对，不计入手动入口数量。

## 桌面灰度记录（macOS 与 Windows）

每个全新 Codex 桌面配置应记录以下结果。未完成的项目须在 GitHub Release 中明示；自动化测试和服务端回执不能替代实际画布观察。

1. 匿名开图及限制提示；输入临时 Key 后不回显、结束会话后清除。
2. 工作台 9 个入口逐项手动预览及保存；对话工具链核对受控创建、同 ID 续改和删除。
3. 通道/平台候选未经明确确认时被拒绝；来源、周期或版本变更后旧候选被拒绝。
4. 关闭/重开资源、结束/重开对话后图形和 Key 均不恢复；窄侧栏下图表与工作台仍可操作。
5. 每项分别记录服务端提交、UI 回执和人工像素观察，不能将任一项替代另一项。

## 发布顺序

1. 推送 `v0.6.0-rc.N`，双包 CI 构建、测试、烟测并生成 SHA-256。
2. CI 创建 Draft Release；维护者核对包内容、哈希及已完成的灰度记录。
3. 自动化门槛、双包和哈希通过后，可手动发布 GitHub `v0.6.0`，并在发布说明中列出仍待完成的桌面灰度项目。不得把未完成的人工项目写成已通过。
4. macOS 与 Windows 桌面灰度完成后再决定扩大分发。公共 marketplace/目录另行准备真实审核材料，不由本流程自动执行。

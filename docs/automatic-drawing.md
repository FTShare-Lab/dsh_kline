# 绘图中的自动识别

## 共用流程与扩展约定

五种自动分析统一由 `tools/automatic_analysis.py` 注册和分发：普通拐点绘图、平行通道、平台框、价格形态与九转。DSH 和 Codex 从这里读取相同的参数默认值、计算结果、候选到绘图对象的映射；图表界面按一份请求映射调用分析，只读取引擎顺序，默认选择第一项，不再根据形态状态或距今远近二次筛选。候选有多项时切换仍更新当前对象；无候选就不画。九转是整段计数序列，不参与候选排序。

统一骨架为：**当前图绑定 → 只读分析 → 按引擎顺序选候选 → 使用结果引用准备绘图 → 应用并核对回执 → 更新同一对象或清除**。自动候选均由受保护的结果引用解析，普通图形也不由浏览器手抄识别锚点；手动选点是明确的另一种输入方式，但沿用同一准备／应用／回执链路。九转以整体序列结果引用替代候选序号，并在行情变化时重新计算。

明确要求自动绘图时，宿主优先调用 `draw_chart(context_ref, symbol, request_id, drawings)`，一次可指定 1–8 个工具，例如 ABC 与下降通道。DSH 和 Codex 共用 `tools/drawing_requests.py` 的请求定义与分析映射；分别适配各自的图表会话及应用回执。合格候选组成一个受保护的绘图修改，一次应用；无候选的工具返回 `no_candidate`，不阻止其他合格工具绘制。`queued`／`delivered` 仍是等待状态，不表示绘制完成。重试保留同一任务编号；Codex 的历史重试不会重新返回旧画布覆盖当前图。

指定日期、价格或修改已有对象时，继续使用 `prepare_chart_edit → apply_chart_edit → get_chart_edit_status`。内部准备步骤不是用户的保存确认。界面「多图」入口调用同一任务流程，不放宽各识别器的条件。

新增图形时先确定类型是“候选结构”还是“整段序列”，再在共享注册表中声明参数、默认值、结果版本和选择方式，最后接入受保护的准备／应用／回执及画布渲染。每个识别器继续负责自己的几何条件、因果时间、拒绝原因和排序：普通拐点按最新锚点、通道按最新终点、平台框在同一截止日按边界质量、价格形态按首次可知日期排序。这些规则并不等价，不能用一个通用评分替代。

`channel_candidates` 和 `range_candidates` 的公开旧接口保留 `closed_daily_only` 可选参数；绘图界面调用它们时显式传 `true`。因此兼容旧接口的非日线分析不等于本版“一键绘图”的日线承诺。

「绘图」只有一个工具选择框，所有图形、形态和九转从这里选择。点击「一键绘图」时默认显示该工具返回的最新合格候选；形态还会标明形成后发生的确认、失效或过期状态。用户可切换候选；没有候选时不强行绘图。九转直接计算并显示数字。所有自动分析只读取当前图已加载的单日线，不抓新行情；A／港／美股当日 K 线只有到达交易所本地的保守收盘时点后才参与计算。

- 水平线：最近严格高／低拐点；趋势线：最近同侧两个已确认拐点；斐波那契：最近两个交替拐点。ABC 要求起点及 A／B／C 共四个交替拐点、三段完整走势，落图保留起点标签 0，不能省略成只有两个波段的 A/B/C 折线，B 回撤为 A 段的 30%–80%，C 段为 A 段的 80%–250% 且越过 A；仍只是价格几何候选，不宣称验证完整艾略特子浪。候选最新锚点距最后一根已收盘日线不超过 30 根，均显示可修改的锚点。没有可信候选时仍可手动选点。
- 平行通道和平台框继续使用既有候选规则，但绘图面板只用已收盘日线调用，优先给出当前候选；可手动选点。平台突破／失效的状态由价格形态规则中的平台候选给出，不从普通矩形推断。
- 双顶／双底、头肩顶／底和平台状态使用共享的 `price_pattern_candidates` 规则。选中对应工具即分析并绘制最近候选；用户可切换候选，图形在同一对象中更新。四类反转形态允许从左到右手动指定 3／5 个锚点，仍须通过同一标准规则，不能凭手点绕过结构验证。平台手动框选走普通平台框工具。
- 九转打开后使用共享的 `nine_count` 引擎自动计算并绘制逐根数字，默认展示最近 30 根已收盘日线以免窄栏图表过密；历史数据仍用于预热计数。当前图的行情变化时重新计算并更新同一个图表对象。

自动候选通过受保护的准备、应用和回执流程直接绘制，关闭「绘图」不会删除图形；用户可通过清除、删除所选对象或撤销绘图移除。任意标签、任意文字、交易结论和无法由已加载行情确定的形状不自动生成。自动选点只是一种可审查的几何建议，不表示交易收益或买卖信号。

对话宿主也能完成同样的两种请求。用户说“分析一下双顶”时只返回分析；说“把最近符合规则的双顶画出来”或明确指定绘图工具时，宿主使用共享引擎返回的第一项合格候选，立即绘图并回报其当前状态，不再要求点击保存。用户指定日期、点位或候选序号时，优先照其选择；无合格候选时说明原因，不强行绘制。DSH 和 Codex 使用同一 Python 规则及受保护的图表应用链路，图上的候选切换和对话中的更新都复用原对象。

选择自动候选时，图表会将候选锚点移入画布中央并按跨度调整缩放。之后仅缩放画布会重新定位图形；行情、标的或来源变化仍须重新分析。用户手动拖动时间轴时保留其视角。

## 选中修改与绘图历史

点击普通绘图可显示锚点，并通过拖动调整；「修改」在图上方展开紧凑的价格输入行，保留各锚点日期和标签，不切换旧工具编辑器。拖动按当前已加载 K 线吸附时间，释放后仍由后端验证并应用，失败不改变正式图形。Escape 可放弃尚未提交的拖动。水平线、趋势线、通道、平台框、斐波那契和标注折线可修改锚点；识别形态、九转及计算序列不允许任意拖动其计算结构。当前上下文的 `selected_drawing_id` 可用于“修改这条线”等自然语言续改，目标不明确时仍须澄清。

工具栏提供撤销、重做及 `⌘/Ctrl Z`、`⌘/Ctrl Shift Z`（也支持 `Ctrl Y`）；文本框内保留文字编辑快捷键。一次多图任务是一个历史步骤。只有取得确认回执的修改才进入历史；撤销只恢复绘图指令，并核对原操作、当前对象与行情绑定，不能恢复其他视图或旧行情上的对象。历史在本页会话内保留最近 40 项，刷新页面不继承。新修改会清空重做分支。DSH 使用本机确认记录，Codex 使用当前 App 连接内的记录，不混用两者的凭证。

自然语言撤销／重做沿用同一历史接口：`prepare_chart_edit` 使用 `kind=drawing_history`、`action=update`、原始已确认操作的 `history_session` 及 `history_direction=undo|redo`，不填对象 ID 或样式字段；重做引用同一个原操作，不引用撤销回执。旧客户端的 `action=create` 仍兼容。不能通过另一次普通坐标修改冒充历史撤销。


## 交易日期与画布状态

上下文的 `time_display` 直接返回交易所本地日期、带时区 ISO 时间及每个绘图锚点的标签。美股使用 `America/New_York` 并随日期处理夏令时；港股使用 `Asia/Hong_Kong`，内地使用 `Asia/Shanghai`。日期形式的锚点输入、区域边界测量和通道预览沿用同一时区；Unix 秒和显式时区 ISO 仍精确匹配原 K 线，不吸附。未知市场保留旧日期解析兼容，明确标记 `legacy_timezone_fallback`，不能当作已确认交易所。

DSH 当前观察反馈分别提供：对象是否与正式图形一致、`time_range_overlap` 是否与实际可视时间范围重叠，以及 `canvas_visibility` 的 `inside_plot`／`partially_clipped`／`outside_plot`／`unknown`。画布状态由浏览器当前绘图区尺寸和 SDK 坐标投影计算，支持水平线、趋势线、通道、平台框、斐波那契及标注折线；计算形态、序列等尚无投影支持的对象仍返回未知。Codex 共享日期口径，未接入此 DSH 浏览器观察的宿主不能声称已获得画布反馈。

这不是像素验证：标签是否被裁剪、均线或其他界面的遮挡仍未核验，`render_verified`、`pixel_verified` 和 `occlusion_verified` 不会因此变为真。应用回执中的状态只对应应用当时；平移或缩放后应读取最新上下文，不沿用历史可见性。

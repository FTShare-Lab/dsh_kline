# v0.6.1 安装与适配验收

## 自动化门槛

- 完整 Node/Python 回归、侧栏构建、DSH/Codex 包清单检查。
- 三系统 × Python 3.11–3.13 的 `test` 分支 CI 通过后再合并 `main`；发布流水线重新构建并烟测同一提交的双包。
- 模拟 Python 尚未就绪：握手、工具列表、准备状态均立即可用；后端就绪后同连接更新工具目录，准备失败有明确状态，连接关闭会结束后端。
- 解压后的实际 Node 入口：自动识别 MCP Apps HTML 能力、CLI 不暴露绘图、桌面资源可读取，合成数据图表创建和受控修改通过。
- 显式 Key 文件：环境变量优先、换 Key 后重新读取、无效/缺失/权限过宽时拒绝，不回显 Key 或路径，不读取未选定的 DSH 凭据。
- 初始化期间的新图表结果在挂载后回放一次，完成渲染后才报告 UI 回执。
- 发布资产下载后重新验证 SHA-256，再将 Draft Release 发布为 v0.6.1。

## 人工验收边界

自动化和协议烟测不代替 macOS/Windows 桌面实际画布验收。仍需按 [v0.6.0 清单](release-acceptance-v0.6.0.md) 记录九个手动入口、窄侧栏、内联/展开视图和资源关闭场景。未完成项目继续在 Release 中明示；不宣称已上架公共目录。

## 安装行为

DSH 与 Codex 分别安装对应归档。Codex 归档自带本地 marketplace，默认根据宿主的 UI 能力选择模式；不依据应用进程名猜测宿主。用户明确指定 `FTSHARE_API_KEY_FILE` 才会复用该文件，不搜索其他应用的配置。用户文件不会随图表会话结束被删除。

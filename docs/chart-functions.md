# 图表函数：确定性计算与受保护绘图

## TA-Lib 计算层（v0.5.0 候选）

标准技术指标统一使用固定版本 TA-Lib 0.8.2；启动时核对版本与 201 个函数，失败即报错，不回退旧公式。`list_ta_functions` 按类别或名称搜索、分页返回输入、参数默认值、输出名；`run_ta_function` 只读取当前图最多 4000 根已加载 OHLCV，不抓新行情、不接收宿主数组或代码，返回简短摘要和 `analysis_only` 结果引用；`read_ta_result` 按输出名分页读取原始序列。每张图最多保留 16 个临时结果，第 17 个起淘汰最早者；被淘汰的引用须重新计算。价格型输入可选择当前 O/H/L/C；`MAVP` 首版使用明确的固定逐根周期。暖机或无定义值为 `null`，形态函数的 0 保留。没有有限输出会如实标记 `no_finite_output`，不编造交易信号；运行函数本身不创建图形、不修改视口，仅白名单结果可在用户明确要求后进入受保护绘图链。

新图表负载与指标摘要标记 `calculation_engine` 版本。已保存的旧负载不后台改写；没有此字段的旧快照不应被称为 TA-Lib 计算结果。现有 MA、成交量均线、MACD、KDJ、BOLL、RSI、ATR、VWAP 的新计算均走 TA-Lib。迁移口径：ATR 首个有效值从旧索引 13 变为 14；MACD 柱从 `2 × (DIF − DEA)` 变为原始 `DIF − DEA`；平盘 RSI 等边界值也可能变化，不能用旧值强行判错。支撑压力、回撤等非 TA-Lib 分析保留原逻辑。TA-Lib 不提供自动通道、艾略特 ABC 或缠论识别；缠论本轮搁置，不安装 CZSC。

网页版自身开图、切换周期／范围和调整指标时，现通过内部 `calculate_chart_indicators` 入口，把当前已加载 K 线交给插件侧统一计算。这个入口不是新的宿主分析工具，不抓行情、不画图；返回 TA-Lib 版本和完整 K 线指纹供网页核对。核对失败会显示错误，不回退旧前端公式。这里的 `calculation_engine` 指指标序列的计算口径；摘要中的支撑压力、最大回撤和基于指标的事件判断仍包含自有规则，不能统称为 TA-Lib 函数结果。网页视觉一致性仍须单独验收。

TA 结果落图白名单支持 `SMA(close, 2..200)`、`EMA(close, 2..200)` 单线和 `BBANDS(close)` 三线：`run_ta_function` 仍是只读计算，但有效结果会标出可选的 `series_line/real` 或 `price_band/upperband,middleband,lowerband`。BBANDS 限定 `timeperiod=2..200`、`matype=0`、上下偏差各大于0且不超过5，三个有限价位须按上／中／下严格排序。用户明确要求画线后，宿主把该 `result_ref` 放入 `prepare_chart_edit` 的 `edit.ta_result_ref`（对应 `kind=series_line` 或 `price_band`），再执行应用与状态核对。插件从本地结果记录读取完整序列，核对同一视图、观察版本、标的、周期、复权与全部已加载 K 线；不要求宿主抄写数组。准备回执中的 `object` 只给 ID、来源、有效根数与哈希；`drawing_guard.parameters` 也仅保留参数 SHA-256 摘要，完整值留在受保护的候选快照。新线或三线组沿用各自稳定 ID，改参数需在新观察版本重新计算，改颜色及删除可直接使用对象 ID。这些是独立的 AI 主图对象，**不是**修改图表已有的 MA/BOLL 指标开关；其他 TA 函数仍不能用此入口绘图。计算成功、对象应用成功和实际像素可见仍分开验收。

序列对象（条件线、价带、柱线）的准备回执统一只返回对象摘要和参数摘要，不回传逐根价格数组；候选快照保留完整序列供应用。`run_ta_function.price_sources` 使用目录中的通用输入名，例如 SMA 为 `{"price":"close"}`，不是底层 TA-Lib 的 `inReal`；默认收盘价可省略此字段。

宿主理解自然语言、选择函数和锚点；插件执行确定性计算、绘图与反馈。不增加插件 LLM、不运行任意代码、不用预置话术代替分析。M2 已接入带标签折线及独立文字 / 数值 / 图标标注。M3 候选仍需更多专业质量样本；M4.1 序列线已在本地网页验证跨周期恢复与跨标的隔离，细小断线空档仍缺足够视觉证据。鼠标选中、拖拽 / 撤销尚未完成。

## 已接入的函数

| 函数 | 必填参数 | 计算口径 |
| --- | --- | --- |
| `fibonacci_retracement` | start_time、start_price、end_time、end_price | 从 A 到 B，回撤价位为 B-r*(B-A) |
| `parallel_channel` | 上述两点及 parallel_time、parallel_price | 复用现有等距 K 线索引三点平行通道 |
| `range_box` | start_time、end_time、lower_price、upper_price | 指定范围的平台矩形，不是平台识别 |
| `labeled_polyline` | points：2至8个 label / time / price | 按给定顺序连接带标签锚点，不是自动识浪 |
| `pivot_candidates` | 可选 left_bars、right_bars、mode、limit | 返回已加载K线中的严格局部高 / 低点候选，只分析不绘图 |
| `regression_channel` | start_time、end_time；可选 multiplier | 对明确区间的收盘价做线性回归并计算统计上下轨，只分析不绘图 |
| `channel_candidates` | 可选 direction、lookback_bars、left_bars、right_bars、min_span_bars、max_candidates | 用已确认拐点提出上升／下降三锚点通道候选，只分析不绘图 |
| `range_candidates` | 可选 window_sizes、max_candidates | 用最新已加载K线的多个固定窗口提出水平平台区间候选，只分析不绘图 |
| `price_series_line` | value_source；可选 condition | 对当前加载K线计算 OHLC、SMA 或 EMA(close, 2–200) 的主图序列线；条件为价格来源/固定价格的大小比较 |
| `conditional_annotation` | annotation_kind、anchor_source、condition；对应的一项内容 | 在当前加载K线中找到最近一根符合条件的K线，创建一枚文字、数值或图标标注 |
| `price_band` | upper_source、lower_source；可选 condition | 在两条当前图价格来源之间按K线填充，空档断开；上边界须始终高于下边界 |
| `price_sticks` | start_source、end_source；可选 condition | 每根命中K线独立绘制一条两价位之间的垂直柱线；等价端点不绘制 |

`pivot_candidates` 是 M3 第一个规则型分析函数：默认左右各2根确认K线，窗口可分别设为1至20根；`mode` 为 `high`、`low` 或 `both`；默认只返回按时间排序的最近20项，最多50项。候选必须严格高于 / 低于左右窗口内每一根K线的最高 / 最低价；相邻等高 / 等低不算拐点，不做平台合并、峰谷交替、趋势判断或形态评分。右侧确认K线不足的末端K线不参与计算；数据不足以形成完整窗口时报错，不补取行情。结果携带每个候选的 side、精确加载K线时间、价格和距最新K线的 bars_ago；`truncated` 标明是否省略较早候选。

`regression_channel` 是 M3 第二个规则型分析函数：必须明确给出首尾时间，均精确对应当前已加载K线，区间至少10根、最多4000根；不自动选起止点。以K线序号为等间距 x 轴，对区间收盘价做普通最小二乘线性回归；通道上下轨分别为拟合线 ± `multiplier × 残差总体 RMS`，`multiplier` 默认为2、范围0.5至5。结果返回斜率、回归线与上下轨首尾价格、残差总体标准差、R²、方向及计算口径。它不做统计显著性或趋势质量判断，不识别自动通道，不绘图；`result_ref` 为 `analysis_only`，不能传给 `prepare_chart_edit`。下轨非正或数据不足时明确报错。回归斜率的单位是每根已加载K线，不是每个自然日。

`channel_candidates` v3 是 M3 的只读选点实验：默认查看最近120根已加载K线，使用左右各2根确认的严格 pivot；上升候选由两个抬高的低点和中间一处高点构成，下降候选对称。两端至少相隔12根K线，基准线首尾价格变化至少3%；候选宽度不得超过锚点区间收盘价中位数的12%，也不得超过基准两点价格变动的2倍。完整锚点区间内，任一影线越轨不得超过通道宽度的25%，越轨K线占比不得超过20%。默认 `scope=current` 仅保留终点距最新K线不超过8根的候选，并独立核对终点之后到最新K线的算术延伸：最大影线超出不得超过宽度的25%，最新收盘须在延伸边界内。`scope=historical` 用于历史结构回看，不核对或推断当前突破。返回最多3组（可设1至5组）的精确锚点、斜率、宽度、越轨数量、越轨比例和最大偏离；同终点／同平行点的重复，或共用平行拐点且斜率与宽度均在10%内的近似几何候选会合并。拒绝原因按规则计数。交易日空档仍按K线序号计算。这些阈值只是保守几何筛选，不是专业质量评分；末端未确认拐点不纳入，也不保证一定有候选。零候选仅表示没有三锚点组合同时满足全部规则，不证明近期缺少拐点或真实走势没有通道；输出另列近期已确认高低拐点数量及这项解释限制。当前模式的区间外延伸仅是数学核对，不是“已确认突破”信号。候选须经人工审查，不自动绘图；其 `result_ref` 同样为 `analysis_only`。

`range_candidates` 是 M3 的只读平台区间原型，区别于按用户给定边界绘图的 `range_box`。默认分别检查截至最新已加载K线的20、30、40、60根窗口；按窗口内最高影线和最低影线确定边界，要求上下边界各至少两次相隔3根以上的触碰，并限制区间宽度、整个窗口和最近10根的收盘价位移及拟合漂移。返回最多3组候选、精确时间／价位、触碰次数与时间、逐窗口拒绝原因；边界和终点完全相同的不同窗口会合并为一组，并报告去重数量。用户可指定1至8个互异的16至120根窗口及最多1至5组候选。没有符合规则的窗口应返回零候选，不强行画平台；这不是突破信号或已确认的专业平台识别，必须人工审查后再单独绘图。`result_ref` 仅供分析，不能直接传给 `prepare_chart_edit`。

上述分析结果 `result_usage=analysis_only`，不能作为普通 `edit.result_ref` 绘图。通道/平台候选另有用户明确确认的专用入口：`candidate_result_ref`、从1开始的 `candidate_number`、`user_confirmed_candidate:true` 必须同时传入 `prepare_chart_edit` 的 `edit`，且只允许创建相应的 `channel` / `rectangle`；插件从引用中读取锚点，不让宿主抄坐标。其他分析结果没有此入口。插件不会因返回候选而自动落图，也不声称候选是专业形态、缠论分型或波浪拐点。

## M4.1 条件序列线

`price_series_line` 的 `value_source` 为 `{ "kind": "open"|"high"|"low"|"close" }` 或 `{ "kind": "sma"|"ema", "period": 2..200 }`。可选 `condition` 使用同一价格单位：`left` 为价格来源，`op` 为 `gt/gte/lt/lte`，`right` 为 `{ "source": 价格来源 }` 或 `{ "constant": 正价格 }`。不接受宿主传来的行情数组、任意代码或公式文本。均线暖机与条件不成立处存为 `null`，渲染时断线；零命中只返回空结果摘要，不能创建空图形。

`conditional_annotation` 复用上述价格来源与条件，但条件必填。`annotation_kind` 选择 `text_annotation`、`number_annotation` 或 `icon_annotation`，并且只传对应的 `annotation_text`、`annotation_value` 或 `annotation_icon`。首版固定选择**最近一次命中的已加载 K 线**，在其 `anchor_source` 价格处生成一枚标注；不是把所有命中 K 线批量标记。函数只返回摘要和结果引用，创建/重算位置及内容使用对应标注 `kind` 的 `prepare_chart_edit(result_ref)`，续改和删除沿用已有对象 ID。零命中不能落图；也不将条件本身解释为买卖信号。2026-10-21 本地网页验证了创建、同ID改字改色与删除，但最新K线长标签在右缘裁切；源码已补文字位置约束，待下一次网页验证。

`price_band` 的上下边界分别使用 `upper_source` / `lower_source`，取值范围同序列线；可选同一种价格条件。每根K线必须是上边界严格高于下边界，否则明确拒绝，不自动交换边界。均线暖机与条件不成立处上下值同时为 `null`，相邻有效点之间填充多边形，跨空档不连接；零命中不能落图。BBANDS 的 TA 引用走同一类对象，但携带中轨，作为一组上／中／下三线修改或删除；普通两边界价带不能伪造中轨。完整序列仅保存在有大小上限的本地结果记录中，宿主只传结果引用。最多4000根、4个 AI 价带；每个价带是一个稳定 ID，创建、重算来源/条件、改样式、删除及反馈沿用受保护流程。2026-10-21 本地网页验证了普通填充可见、同ID改色与删除；BBANDS 三线视觉另行核验。反馈可确认指标注册，不证明实际像素可见。`show_fill` 不是价带参数，不能套用平台框字段。

`price_sticks` 是 STICKLINE 的受控首版：两端分别取 `start_source` / `end_source` 的 OHLC 或 SMA(close, 2–200)，可使用同一种价格条件。每根命中K线独立画一条垂直柱线，不跨空档连接；相等端点为零长度，跳过而不是伪造可见对象。两端可交叉，不自动交换。最多4000根、4组对象；完整序列留在受限本地结果记录，宿主只传结果引用。创建、重新计算、改颜色、删除走受保护链路；源码和自动测试已接通，且已加载到 56790 本地实例，网页像素验收仍待下一轮，不等同于完整通达信 STICKLINE 语义。

计算只返回摘要与 `result_ref`，完整序列保存在上限256 KiB的本地结果记录；最多4000根当前加载K线、8个 AI 条件序列线对象。创建、修改来源/条件、改颜色和删除均走当前图的准备→应用→状态核对，整条线只有一个稳定 ID。序列只画在价格主图；切换周期后不同周期的对象保留但隐藏，返回原周期还要核对 K线身份，不能拿旧结果给新周期套图。前端复用已有 KLineCharts 指标渲染，不重置行情、原指标或视口。反馈可确认指标注册，但不是像素可见性证明。

斐波那契默认比例为 0、0.236、0.382、0.5、0.618、0.786、1；可指定1至16个递增、不重复的0至1比例。0位是终点 B，1位是起点 A；允许上涨及下跌，拒绝等价锚点。不支持扩展位或对数计算；不根据屏幕像素插值算价格。0.618线默认加粗。

所有时间必须精确落在已加载 K 线上；沿用日期 / 带时区 ISO / Unix 秒字符串规则。起点早于终点，不吸附交易日、不补取行情、不自动选最近高低点。首轮重点仍为日线 / 周线，分钟沿用来源与权限限制。

## 接口与数据流

1. `list_chart_functions` 返回已实现函数、版本、参数和限制；不是整个金融公式语言。
2. `get_chart_context` 获取本对话当前视图、观察版本及对齐的命名来源。
3. `run_chart_function(context_ref, expected_revision, chart_session, symbol, function, parameters)` 只计算，返回 `result_ref`、规范化参数、简短结果及 `calculation_ms`。不创建候选快照或修改图表。
4. `result_usage=guarded_drawing` 的结果调用原有 `prepare_chart_edit`，在 `edit` 内指定 `result_ref`、对应 `kind` 与 `action`。更新还需已有 `object_id`；可以附加名称 / 颜色，以及适用的中线 / 填充开关。引用与直接锚点、边界、比例互斥。`pivot_candidates`、`regression_channel` 没有落图入口；通道/平台候选只在用户明确选定后使用上述专用候选入口。
5. 继续 `apply_chart_edit` 和 `get_chart_edit_status`。计算结果、准备候选、排队、应用确认是不同状态；对象 API 反馈不等于像素核验。

函数名与绘图类型的对应关系：fibonacci_retracement → fibonacci_retracement，parallel_channel → channel，range_box → rectangle。

labeled_polyline → labeled_polyline。调用参数 points 中每个点都有明确 label、time 和 price，标签在组内唯一、时间严格递增，不自动排序 / 吸附 / 选择点位。标签为1至16个字符，既可用 A/B/C、1/2/3/4/5，也可用其他名称，不限制为预置波浪模板。

## 独立文字与数值标注

通过原有 `prepare_chart_edit` 创建 `text_annotation`、`number_annotation` 或 `icon_annotation`，都需提供明确的 `anchor_time` 和 `anchor_price`。文字 / 数值分别使用 `annotation_text` / `annotation_value`；图标使用 `annotation_icon`，当前支持 `arrow_up`、`arrow_down`、`diamond`。锚点必须精确对应当前加载的 K 线；数字按输入数值显示。更新 / 删除必须使用当前观察中的对象 ID。标注与其他 AI 图形共用同一来源对齐、周期保护、应用确认、对象反馈和刷新恢复流程；不自动选择锚点或计算数字。

创建文字标注示例：

```json
{"kind":"text_annotation","action":"create","anchor_time":"2026-10-16","anchor_price":34,"annotation_text":"前高","name":"前高说明","color":"warning"}
```

创建数值标注时改用 `kind:"number_annotation"` 和 `annotation_value:0.618`；后续按当前观察读取的 `object_id` 修改或删除。

创建菱形图标时使用 `kind:"icon_annotation"` 和 `annotation_icon:"diamond"`；标注名称会显示在图标旁。图标通过线段图元渲染，不依赖系统 emoji 字体。

斐波那契所有水平位、价位和比例标签归一个稳定对象 ID 管理；创建、锚点 / 比例更新、颜色 / 名称更新、整体删除均经过同一受保护链路。样式更新和删除不需要重新计算；几何更新建议重新运行函数，直接传引用，不让宿主重新手算价位。

## 带标签折线：只改一个点

创建时运行 labeled_polyline 函数，沿用 result_ref → prepare / apply / status；每组的折线和标签归一个稳定 ID 管理。数字标签也是文字，不包含独立数值格式化或自动波浪解释。

修改 C 点时，只向 prepare_chart_edit 的 edit 传入以下字段，不重新运行创建函数，不让宿主抄写 A/B 等邻点：

```json
{
  "kind": "labeled_polyline",
  "action": "update",
  "object_id": "从当前观察读到的完整对象ID",
  "point_label": "C",
  "point_time": "2026-10-19",
  "point_price": 31
}
```

可以只修改时间或价格，也可同时修改；点名必须明确存在。插件从原对象保留其他点，校验修改后的顺序和全部锚点，失败不改变原图。change.point_changes 给出本次候选中实际变化的点；这仍是候选差异，不代替应用回执。

整组名称 / 颜色更新直接使用同一 object_id 及 name / color；删除只传 kind、action、object_id，不逐条删标签或线段。点名是组内身份，不是全局图形 ID；若多组都含 C 或组名重名，宿主须先澄清，不能按最近对象猜测。

本步不支持更新时整组传 points 或创建 result_ref 重写已有对象，也不支持增删单点 / 重命名单点 / 调换顺序；这些需求另行实现。当前最多30组，每组2至8点；后续缠论长序列接入需单独设计容量，不直接套用该上限。

## 结果复用与边界

- 相同视图、相同行情和规范化参数产生同一引用。修改其他对象或视口不改变价格计算；准备 / 应用仍核对新鲜观察版本与完整当前状态。
- 引用绑定运行宿主、上下文、对话、视图、标的、周期、分钟粒度、复权、来源元数据及完整已加载 OHLCV 指纹。数据改变须重算，不能跨图借用。
- 本阶段最多4000根加载数据、每视图64个函数结果、30组斐波那契对象；不自动删除旧结果。结果文件只保存绑定指纹、函数版本、参数和紧凑结果，不复制行情或凭据。
- 函数引用不提供跨进程或重挂载复用保证；重挂载后先读新上下文并重算。已确认图形仍沿用现有同宿主检查点恢复协议，不扩大恢复承诺。
- 创建参数不全时澄清；用户明确授权宿主提出锚点时可由宿主分析。要求先提案时，确认前不得准备或应用。
- 不开放鼠标拖拽、撤销、手动对象 AI 修改、自动平台 / 波浪识别或缠论。当前通道候选只做规则型几何提议，不等于自动识别质量已验收。没有“专业判断正确”或收益保证。

## 验收与后续

### 第一期「专业绘图」界面

复用盘点：KLineCharts 9.6 的基础覆盖物与交互适合旧「画线」入口，但直接创建它们不会自动获得当前 AI 对象的来源绑定、稳定 ID、版本保护和应用反馈。因此第一期不把内置覆盖物另开为第二条落图通道。水平／趋势线、通道、平台框、斐波那契和 ABC 均复用仓库已有 AI 覆盖物及受保护对象；SMA／EMA 复用序列线，BOLL 复用三轨价带。KLineChart Pro 只参考工具选择、参数面板的组织方式，不复制代码或整包接入；extension 需要 10+，与当前 9.6 不兼容；HQChart 仅供函数分类参考，不引入公式解释器。若未来复制任一外部实现，先核对其许可证和附加条款。

图表工具栏新增「专业绘图」：SMA、EMA、BOLL、水平线、趋势线、平行通道、平台框、斐波那契、ABC 标注。201 个 TA-Lib 函数仍可通过宿主只读查询和计算，但界面仅开放这三类可绘制指标；既有 MA/BOLL 指标开关与新建的受保护绘图对象彼此独立。

用户在界面选 K 线锚点、改价与参数后，先得到未保存提案；再次确认才执行相同的计算／结果引用、准备、应用、状态核对流程。工作台只展示当前标的和周期的精选 AI 对象，可按完整 ID 改名、改色、改参数或删除；Agent 创建的同类对象也会进入清单，反向亦然。ABC 是指定 A/B/C 点的折线标注，不是自动识浪，修改时一次只更新一个有名点。来源、观察版本或图表切换后，提案失效；不通过旧引用重新落图。

旧「画线」手绘对象照常显示和保存，本期不自动迁移成可由 Agent 修改的对象。界面应用状态只证明网页接受了对象，不证明像素或选点质量；仍需集中网页验收。拖拽、撤销、缠论和自动形态判断不在本期。

自动化分别检查独立公式价位、重复结果一致性、函数引用绘图、稳定 ID 续改 / 删除、单点修改不改变邻点、来源隔离、错误拒绝、跨语言应用回执、对象反馈、恢复检查点及渲染模板。真实网页自然语言验收另行记录，不用隔离测试冒充网页通过。

耗时字段包含读取 / 校验 / 保存结果，不能当作纯算法耗时。token 与端到端提速尚无对照数据，不宣称已节省。本文描述 v0.5.0 发布候选；新指标计算以 TA-Lib 口径为准，旧快照保持原状。自动分析算法的专业质量仍另行验收。

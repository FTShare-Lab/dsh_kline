# dsh_kline v0.2.0 发布后验收清单

状态：**已发布，待持续真实环境验证**（正式版本：`v0.2.0`；基线：`v0.1.8`；Harness：`0.1.2-rc.1`；已验证 Better Sidebar：`0.18.0`）。
本文档把此前未覆盖的真实环境范围细化为可勾选步骤。执行完成后请把“实测结果”栏回填（可直接编辑本文档或另附记录），作为后续维护与补丁版本的依据。

自动化基线（本次核查已重新跑绿）：Python 90 passed、Node 52 passed、`verify:package` 通过、`git diff --check` 通过。

前置条件：

- 当前 Harness Web（本页所运行的宿主）已加载 rc.2 本地候选（本次会话实测该宿主 MCP 返回与 rc.2 代码一致的行为，如美股/港股分钟接口按市场限制提示；如在其它 profile 验收请先确认同样加载 rc.2）。
- 双 AI 并发项需要能同时运行两个真实对话的模型配置（付费模型），以及对话所需的数据权限。
- FTShare 相关标的验证需要当前套餐可用的 API Key；其余场景可用免费指数行情或 `analyze_kline_rows` 外部数据完成。
- 每项请同时观察 DevTools Console（记录是否出现 error / 未捕获异常 / 告警）。
- 若当前 FTShare 套餐无美股/港股权限：把 A2 的 `AAPL.US` 换成另一只你可覆盖的标的（如 A 股 `000858.XSHE`）。并发归属验证与具体市场无关；A5 外部 rows 场景完全不受权限限制。
- 双 AI 并发的关键是**两个对话真正同时处于运行中**（而不是排队等待）；请确认模型与配额允许并行，否则无法制造竞争窗口。

## A. 双 AI 并发端到端链路

覆盖：两个真实对话同时产出行情 / 外部 rows，Tab 自动创建、后台结果归属与旧图恢复。

| # | 步骤 | 预期结果 | 实测结果 | 通过/失败/备注 |
|---|---|---|---|---|
| A1 | 打开两个不同对话（分栏或两个窗口），都停留在 rc.2 | 两个对话均可独立使用；Better Sidebar Tab 模式下各自对话的默认 K 线入口只添加一次 | | |
| A2 | 几乎同时发起：对话 1「分析 600519.XSHG 60 根日 K」，对话 2「分析 AAPL.US 30 根日 K」 | 两个图表会话各自生成，结果归属到各自对话；不互相覆盖、不串图 | | |
| A3 | 一个完成后，将另一对话切走再切回 | 各自图表、关键点位、标注恢复；数据源与最新价一致 | | |
| A4 | 同一对话内先请求标的 A 再请求标的 B，让较慢的 A 结果后到 | 晚到结果不得抢走 B 的图表（late-result 归属正确，与现有单测语义一致） | | |
| A5 | 两个对话都用外部 rows（`analyze_kline_rows` 自定义标的）并发分析 | 归属正确、来源标注正确 | | |
| A6 | 全过程切换对话、关闭/重开 K 线 Tab | 隐藏时图表 DOM 卸载并停表，恢复后数据/标注完整；无重复渲染告警 | | |

# v0.6.14 · 资料刷新、加载状态与错误诊断

- 资讯错误页和空结果页提供带刷新图标的重新加载按钮；已有资讯及公司资料页也可直接刷新。请求期间显示“正在重新加载… / Reloading…”，图标旋转、按钮禁用，避免重复请求。
- 资讯／公司页的底部刷新只重新请求当前标的资料，不再等待无关指数、行情或重新加载图表。手动刷新绕过预取和后端缓存；资料请求超过 45 秒时恢复可重试状态，包括忽略 AbortSignal 的 MCP App 宿主。
- 将上游服务故障、连接失败、超时、Key 校验失败、接口访问权限、限流和接口不兼容分别解释；展示能够确认的 HTTP 状态码。FTShare 的 HTTP 502 不再统一提示用户检查本地网络。
- 刷新失败保留上次成功取得的内容并标明可能过期，保留原成功时间；失败请求的时间标为“最近请求”，不会显示成成功更新时间。资讯失败时不再因为公司资料成功而提示“资讯已更新”。
- Codex App 使用新的图表资源标识，避免升级后继续命中旧版页面缓存。
- 修复公司模块部分成功时只显示警告、遮掉已取得内容的问题；识别 SDK 的结构化业务错误，缺失接口显示为暂不支持。

本次修复插件的刷新与反馈流程。FTShare 新闻语义检索服务的 502 仍需服务端修复，本版不宣称新闻服务已经恢复。不会新增、迁移或发布用户凭据；既有 App 会话 Key 和外部凭据文件的使用范围不变。

GitHub 附件提供 DSH TGZ、Codex ZIP 及各自 SHA-256。npm 同步使用已核对的同一份 DSH TGZ 发布 0.6.14；安装命令与版本保持一致。保留现有 UTM 渠道参数，npm 与 Release 入口继续指向包页面及最新发行版。详见[验收记录](release-acceptance-v0.6.14.md)。
